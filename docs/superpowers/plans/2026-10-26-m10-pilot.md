# M10 Pilot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Strangers can reach Casa Fiorella at a public HTTPS URL and book real reservations on the demo calendar. Every conversation is recorded under `source=pilot` with feedback and handoff outcomes. Abuse, cost, privacy and secrets are handled well enough that leaving it up for weeks is safe.

**Architecture:** Two PRs, never stacked.
- **Part A (code, this branch `claude/m10-pilot-dbf663`):**
  - a production guard
  - pilot tagging
  - the feedback log and handoff outcomes
  - abuse limits (WS rate limits, Turnstile, booking and email caps)
  - the retention job, a deep health check and the privacy notice
  - `pnpm release`

  Everything works locally and in CI with no new accounts: Turnstile has official always-pass test keys.
- **Part B (deploy, a new branch from `main` after A merges):**
  - one Dockerfile plus `deploy/compose.prod.yml` with Caddy (automatic Let's Encrypt HTTPS)
  - `pnpm smoke <url>`
  - a scheduled health workflow
  - `docs/deploy.md`, `docs/pilot.md` and the learning note
  - the first release

  The deploy itself is the user's, step by step.

**Hosting (user picked 2026-10-26):** Oracle Cloud Always Free **Ampere A1** VM (Ubuntu, arm64) running Docker Compose. Caddy terminates HTTPS for a free **DuckDNS** hostname (`<name>.duckdns.org`). Cloudflare **Turnstile** guards chat start (free, works without the domain being on Cloudflare). Fallback if A1 has no capacity: a Cloudflare Quick Tunnel from the Mac, testing-grade only.

Limits checked on official pages 2026-10-26:
- **Oracle:** A1 gives 2 OCPU / 12 GB total; 200 GB disk; 10 TB/month egress. Idle reclamation applies when p95 CPU, network **and** memory are all below 20% over 7 days.
- **Cloudflare:** a named Tunnel needs a domain on Cloudflare, which costs money. Quick Tunnels allow 200 in-flight requests, have no SSE and no uptime guarantee.
- **Turnstile:** free plan with 20 widgets, unlimited challenges, 10 hostnames per widget.

**Tech Stack:** Fastify 5 + `@fastify/websocket`, ioredis, BullMQ, Drizzle/Postgres 17, Next.js 16, Vitest, Playwright, Docker Compose, Caddy 2, `tsx` for scripts.

**Spec:** `docs/superpowers/specs/2026-10-22-frontdesk-design.md`: §12 (pilot), §10 (source separation), §7 (spend cap), §11 (errors), §14 M10 row. Earlier notes: `docs/learning/*.md`.

## Global Constraints

- **$0:**
  - production runs `LLM_PROVIDER=gemini`, `LLM_TIER=free`, `SPEND_CAP_USD_MONTHLY=0`
  - Gemini billing stays **off** (a user-checked runbook step: code can't see billing)
  - no paid Oracle upgrade, no paid domain
- **Production guard:** with `NODE_ENV=production`, the api **and** worker refuse to start when:
  - `LLM_TIER`≠`free`, `SPEND_CAP_USD_MONTHLY`≠`0`, `LLM_PROVIDER`≠`gemini`, or `LLM_RECORD`≠`0`
  - `GEMINI_API_KEY_2` is set
  - `FRONTDESK_NOW` is set
  - `CONVERSATION_SOURCE`≠`pilot`
  - `TURNSTILE_SECRET_KEY` is unset
  - `OWNER_EMAIL`/`OWNER_PASSWORD_HASH` are unset
  - any `WEB_ORIGINS` entry is not `https://`

  The error names the variable, never its value.
- **Source separation (§10):** api conversations take their source from `CONVERSATION_SOURCE` (`live` default, `pilot` in production). `eval` is never allowed in the api.
- **No PII in logs:** no caller name, phone, email, caller text or session id in any log line, in api, worker or Caddy. Caddy access logs stay off. Redis keys that are derived from a contact use `sha256(normalizeContact(c)).slice(0,16)`, never the raw value.
- **Secrets:**
  - production env lives in `/opt/frontdesk/.env.production` on the VM: `chmod 600`, owned by the deploy user, never committed
  - `.gitignore` covers `.env*` except `*.example`
  - scripts never echo env values
- `packages/core` stays pure: new ports are interfaces only.
- `audit_log` stays append-only for INSERT/DELETE/TRUNCATE. The only allowed UPDATE is the retention redaction (A4).
- Copy: privacy notice and limit messages exactly as written in the tasks below.

## Decisions ledger (also written to the shared notes folder as `m10-pilot-rulings.md`)

| # | Decision | Why |
|---|---|---|
| 1 | Oracle A1 VM, shape **2 OCPU / 6 GB**, Ubuntu 24.04 arm64 | The stack uses ~2–3 GB, so memory sits above 20% and the VM never counts as "idle" for reclamation. The runbook verifies with `free -m`. |
| 2 | DuckDNS hostname + Caddy auto-HTTPS | $0 and a stable URL. DuckDNS is on the Public Suffix List, so Let's Encrypt limits are per-subdomain. |
| 3 | Images are **built on the VM** (`docker compose build`) | `NEXT_PUBLIC_*` values are baked in at build time; an arm64 build on the VM avoids a registry and multi-arch CI. |
| 4 | Turnstile token is required to open a **new** session; resuming with a valid `sessionId` needs none | The session id is already an unguessable credential. The token travels as the `?ts=` query param; logs already strip query strings, and Caddy logs are off. |
| 5 | WS limits: per IP 10 new sessions/hour, 3 concurrent sockets, 300 turns/day; per session 8 turns/minute, 40 turns total | A real booking takes ≤10 turns. These numbers keep one abuser far under the Gemini free-tier RPD, which the existing rate-limit wrapper still enforces globally. |
| 6 | Bookings: **2 per contact per business-day of creation**. Checked at propose, counted after a successful execute. | A refusal before the read-back is the clearest UX. A race can overshoot by one; that's acceptable. Over the cap the agent says to call, without a handoff, so abuse can't flood the owner queue. |
| 7 | Emails: **3 per recipient per day**, **50 global per day**, enforced in the worker (the single sender) | Over the cap the email is skipped and audited `email_failed` with reason `daily_cap`. No retry and no handoff. The booking stands (§11). |
| 8 | Retention: after **30 days**, pilot PII is redacted (not rows deleted). This covers turns text, handoff summary/transcript/notes, feedback comment, audit `args`/`result` contact fields, and the demo-calendar event's name/contact/notes. | Counts, outcomes, ratings and latencies survive for metrics. `audit_log` gets one narrow, flag-guarded UPDATE path. Gmail "Sent" can't be cleaned with `gmail.send` scope, so `docs/pilot.md` has a monthly manual step. |
| 9 | OAuth: **publish the consent screen to "In production"** (unverified, single user) | Testing mode expires refresh tokens after 7 days. Unverified production shows a warning screen to the one account but issues long-lived tokens. `/health/ready` plus the scheduled workflow alert if the token ever dies. |
| 10 | Behind Caddy, `TRUST_PROXY` = the compose network CIDR (`172.30.0.0/24`), and the web owner proxy forwards `X-Forwarded-For` only when `TRUST_FORWARDED_FOR=1` | Caddy replaces any client-sent XFF, so per-IP limits see the visitor. Locally nothing changes. |
| 11 | Release tag is `vYYYY.MM.DD` from the America/New_York date. A second release on the same day gets `vYYYY.MM.DD.2`. `pnpm release` commits `CHANGELOG.md` and makes an annotated tag locally; **pushing is a separate, asked step**. | Tagging is outward-facing once pushed. |
| 12 | Health alerting is a GitHub Actions cron every 6 h hitting `/health/ready` | It's free, and a failed scheduled run emails the repo owner. |

## Review Focus

1. **Spoofed `X-Forwarded-For` to dodge per-IP limits.** Expected: the api uses the XFF only from `TRUST_PROXY` peers. Pinned in A5 › "ignores X-Forwarded-For from an untrusted peer".
2. **Bot check skipped by a resume with a made-up session id.** Expected: an unknown `sessionId` without a valid token is rejected, not given a fresh session. Pinned in A6 › "unknown sessionId without a token is refused".
3. **Same email in different case/whitespace to dodge caps.** Expected: caps key on `normalizeContact`. Pinned in A7 › "counts ' A@x.com ' and 'a@x.com' as one contact" and A8 › "recipient cap ignores case".
4. **Retention touching live/seeded or recent rows.** Expected: only `source='pilot'` rows older than 30 days are redacted; others are untouched; a second run is a no-op. Pinned in A9 › "leaves live, seeded and recent rows untouched" and "is idempotent".
5. **Health endpoint leaking secrets or error details.** Expected: `/health/ready` returns only `{ok, checks:{redis,postgres,google,worker}: "ok"|"fail"}`, never messages. It's cached 5 min, so it can't be used to hammer Google. Pinned in A10 › "never includes error text" and "caches the google check".
