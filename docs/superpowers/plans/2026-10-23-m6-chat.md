# M6 Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A caller can book a table at Casa Fiorella by chatting at `/talk` in the browser. The api runs the unchanged M3 agent loop over a WebSocket, keeps sessions in Redis, and stores every turn's latency, tokens and cost in Postgres.

**Architecture:** Two PRs, never stacked. **Part A** (`m6-chat-a`): `apps/api` becomes a Fastify server with one WebSocket route `/ws`. Each socket is bound to a server-issued session in a Redis `SessionStore`. Every `user_text` runs core's `runTurn`, and each `ServerMessage` it emits is relayed to the socket. Adapters are picked from env, and each turn is written to `turns`. **Part B** (`m6-chat-b`, branched from `main` after A merges): `apps/web` (Next.js, `/talk` only, shadcn/ui + Tailwind), Playwright e2e against web + api with a keyless scripted LLM, and a CI `e2e` job.

**Tech Stack:** Node 24, TypeScript ^5, Fastify ^5 + `@fastify/websocket` ^11 (`ws`), `ioredis` ^6, Drizzle (M5 `@frontdesk/db`), BullMQ (M5 `@frontdesk/worker`), Next.js ^16 (App Router) + Tailwind v4 + shadcn/ui, `@playwright/test` (Chromium only), Vitest, `tsx`.

**Spec:** `docs/superpowers/specs/2026-10-22-frontdesk-design.md` (§3 one turn end to end, §8 protocol + latency budget + per-turn record, §11 WebSocket drop, §13, §14 M6 row).

## Global Constraints

- Protocol (§8). Client → server: `user_text{text, timings{speechEnd, sttFinal}}`, `interrupt`, `tts_started{turnId, at}`. Server → client: `agent_delta`, `agent_sentence`, `pending_action`, `action_result`, `handoff`, `turn_metrics`. The Zod types live in `packages/core/src/protocol/messages.ts`. This plan adds two server messages there: `session` and `error`.
- The M3 loop (`runTurn`) is used **unchanged**. The api only relays what it emits. It never calls `confirmAndExecute`, `propose` or any Calendar write; `tests/lint/write-path.test.ts` must keep passing.
- Latency budget p95 (§8): LLM time to first token **1500 ms**, each tool call **800 ms**, chat first token **1800 ms**. Turns over p95 are flagged.
- Per-turn record (§8): `stt_ms, llm_ttft_ms, llm_total_ms, tool_ms[], tts_start_ms, total_ms, tokens_in, tokens_out, cost_usd`, using M5's `turns` table as is (no migration).
- WebSocket drop (§11): the client reconnects with its session id, state is restored from Redis, and a pending action survives until it expires (`PENDING_TTL_MS` = 300 000).
- Redis holds session state, pending actions and slot locks (§3). Postgres holds conversations, turns, the audit log and handoffs (§3).
- Adapters: Google Calendar via `createGoogleCalendar` when `readGoogleEnv()` returns credentials, else `InMemoryCalendar`. Mailer is always `QueueMailer`, so a confirmed booking enqueues the M5 job and the worker sends it.
- LLM: `createLLM(env, …)` (Gemini by default). `LLM_PROVIDER=scripted` selects the api's deterministic `ScriptedLLM`, which needs no keys and is used only by tests and e2e.
- `packages/core` stays lint-enforced pure. `tests/lint/workspace-references.test.ts`: tsconfig references must match `workspace:*` deps.
- Keep dependencies lean: ESLint 10 ran out of memory on huge type packages before. No icon library, no state library, no UI kit beyond shadcn's copied components.
- Secrets are never logged or printed. Never echo `.env` values.
- Web scope: `/talk` only. No dashboard pages, no voice. Simple, tidy styling (M8 restyles it).

## Review Focus

1. **A crafted client message executes an action.** For example `{type:"confirm", actionId}`, extra fields on `user_text`, or a `user_text` sent while no read-back was shown. Expected: anything that isn't a valid `ClientMessage` gets `error{code:"bad_message"}` and runs nothing, and a valid `user_text` only reaches `runTurn` as caller text. Pinned in A4 › "rejects a crafted confirm message and writes nothing" and "rejects unknown fields on user_text".
2. **A page on another site opens a socket to the api** (cross-site WebSocket hijacking) and talks as the visitor. Expected: an upgrade whose `Origin` isn't in `WEB_ORIGINS` is refused. Pinned in A5 › "refuses an upgrade from a foreign origin".
3. **A client picks or guesses a session id.** Expected: an unknown `sessionId` on connect gets a fresh server-issued id (`sess_<uuid>`), never the client's string. Pinned in A4 › "never adopts an unknown client session id".
4. **Flooding `user_text` while a turn runs** stacks paid LLM calls. Expected: one turn in flight per socket; extras get `error{code:"busy"}`. Pinned in A4 › "answers busy while a turn is in flight".
5. **Dates lose their type through Redis.** `PendingAction.slot.start` and `SessionState.offeredSlots[*].start` are `Date`s, and plain JSON turns them into strings, which breaks the gate's re-check after a reconnect. Pinned in A2 › "round-trips Dates in session and pending action" and in the A5 smoke test "confirms after reconnecting".

### Task A3: Scripted LLM, latency budget, turn record

**Files:** Create `apps/api/src/llm/scripted.ts` + `.test.ts`, `apps/api/src/metrics/latency.ts` + `.test.ts`, `apps/api/src/metrics/turn-record.ts` + `.test.ts`. Modify `packages/llm/src/wrappers/spend-cap.ts` + `packages/llm/src/index.ts` to export the existing `costUsd(usage, price)`.

**Interfaces — Produces:**
- `class ScriptedLLM implements LLMProvider` (`model = "scripted"`): a deterministic receptionist for tests and e2e, keyed on the latest message in `req.messages` (caller text is unwrapped from `<caller_message>` and HTML-unescaped with core's helpers or a local inverse). Every text reply starts with `@meta {"confidence":0.9,"onTopic":true}\n` and contains no times, dates or prices, so the grounding check always passes. Usage chunk `{inputTokens: 120, outputTokens: 30}`. The rules, in order:
  - `/table for (\d+) on (\d{4}-\d{2}-\d{2}) at (\d{1,2}:\d{2})/i` → tool call `check_availability {date, time, partySize}`.
  - `/make it (\d{1,2}:\d{2})/i` → `check_availability` with the date and party size of the last `check_availability` call in history.
  - `/^\s*([^,]+),\s*(\S+@\S+)\s*$/` → `book {slotId, name, contact, partySize}`, where `slotId` is the slot from the last `check_availability` result whose `time` equals that call's requested time.
  - The last message is a `check_availability` tool result → "That time is open. What name and email should I use?" if the requested time is among the slots, else "That time is full. Could you try another time?"
  - Anything else → "How can I help with a reservation?"
  - `generate` (only `purpose:"confirmation"`): `/change|actually|instead/i` → `change`; `/^(no|nope)\b/i` → `deny`; `/^(yes|confirm)/i` → `confirm`; else `unrelated`. All at confidence 0.9. Any other purpose throws `LLMError("invalid_output")`.
- `buildLLM(env: Record<string,string|undefined>, redis: Redis): LLMProvider` in `apps/api/src/llm/build.ts`. `scripted` → `ScriptedLLM`. Otherwise `createLLM(env, { rate: new RedisRateLimitStore(redis), spend: new RedisSpendStore(redis), cache: new RedisCacheStore(redis), recordings: new MemoryRecordingStore() })`.
- `LATENCY_P95_MS = { llmTtft: 1500, tool: 800, chatFirstToken: 1800 } as const` and `overBudgetFlags(m: { llmTtftMs?: number; toolMs: number[]; firstOutputMs?: number }): string[]`. The flags are `"over_p95_llm_ttft" | "over_p95_tool" | "over_p95_first_token"`. Equal to the budget is not over.
- `toTurnRecord(input: { id; conversationId; turnIndex; callerText; result: TurnResult; timings: {speechEnd?; sttFinal?}; firstOutputMs?: number; price: Price; now: Date }): TurnRecord`. It reads the `turn_metrics` message out of `result.messages`, rounds every ms to an integer, sets `sttMs = sttFinal − speechEnd` when both are present (else null) and `ttsStartMs = null` (M7), and computes `costUsd = costUsd({inputTokens, outputTokens}, price)`. `flags` = `result.flags` + `overBudgetFlags(...)`.

### Task A4: Chat connection (one socket ↔ one session)

**Files:** Create `apps/api/src/chat/connection.ts` + `connection.test.ts`, `apps/api/src/chat/conversation-log.ts` (interface + in-memory version).

**Interfaces:**
- Consumes: A1 messages, A3 `toTurnRecord`, core `runTurn`, `AgentDeps`.
- Produces:
  - `interface ConversationLog { start(c: {id; source:"live"; startedAt}): Promise<void>; recordTurn(t: TurnRecord): Promise<void>; end(id, e: {endedAt; outcome; handoffReason?}): Promise<void> }`. `PgConversations` satisfies it structurally. `InMemoryConversationLog` records calls for tests.
  - `interface ChatContext { deps: AgentDeps; log: ConversationLog; price: Price; newSessionId: () => string; logger: { error(obj: unknown, msg: string): void } }`
  - `interface ChatSocket { send(text: string): void; close(code?: number): void }`
  - `openChat(socket: ChatSocket, ctx: ChatContext, requestedSessionId?: string): Promise<{ onMessage(raw: string): Promise<void>; sessionId: string }>`

Behavior:
- **Open:** if `requestedSessionId` loads a session from `deps.sessions`, resume it. Otherwise make a new id with `ctx.newSessionId()`, save `newSession(id, now)` and call `log.start`. Then send `session{…}` with its transcript, the pending action if `getPending` returns one not yet expired, and `handoff{reason, message: alreadyHandedOffMessage(config)}` if the session was handed off.
- **Message:** `JSON.parse` and `ClientMessageSchema.safeParse`. On failure, send `error{bad_message}` and do nothing else. `interrupt` and `tts_started` are accepted no-ops (M7). For `user_text`, if a turn is in flight send `error{busy}`. Otherwise record `t0`, call `runTurn(deps, {sessionId, text}, emit)`, and have `emit` send each message and note `firstOutputMs` at the first `agent_sentence|agent_delta|pending_action|handoff`. Afterwards load the session for `turnIndex = session.turn`, then call `log.recordTurn(toTurnRecord(...))` and, if `result.handoff`, `log.end(..., {outcome:"handoff", handoffReason})`. Log failures are passed to `logger.error` and never reach the caller. If `runTurn` throws, send `error{server_error, "Sorry, something went wrong. Please try again."}`.
