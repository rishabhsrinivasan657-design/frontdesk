# M7 Voice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A caller can book a table at `/talk` by voice in Chrome: speech in through the Web Speech API, each reply sentence spoken as it arrives, barge-in that stops speech and cancels the in-flight reply, and per-stage voice latency (`stt_ms`, `tts_start_ms`) stored per turn.

**Architecture:** One PR (`claude/m7-voice-d18400`). The browser gets two small interfaces, `SpeechToText` and `TextToSpeech`, with Web Speech implementations, a `Speaker` that queues sentences, and a `VoiceController` that ties mic, speaker and chat socket together. Voice only produces caller **text**: a final transcript is sent as an ordinary `user_text`, so a spoken "yes" goes through the same gate and classifier as a typed one. The api gains real `interrupt` handling (an `AbortSignal` into core's `runTurn`, honoured only before anything is written) and `tts_started` handling (stores `tts_start_ms`).

**Tech Stack:** Web Speech API (`SpeechRecognition`/`webkitSpeechRecognition`, `speechSynthesis`), Next.js 16 + React, Fastify WS (M6), Vitest (web units run in node with fakes, no jsdom), Playwright (Chromium). **No new dependencies.**

**Spec:** `docs/superpowers/specs/2026-10-22-frontdesk-design.md` §8 (protocol, voice v1, latency budget, per-turn record), §13 (Playwright mocks voice at the `SpeechToText` interface), §14 M7 row ("a voice booking works in Chrome; per-stage latency is logged").

## Global Constraints

- Protocol (§8): client → server `user_text{text, timings{speechEnd, sttFinal}}`, `interrupt`, `tts_started{turnId, at}`. This plan adds **one** server message: `interrupted{}` (the turn was cancelled; the caller may speak again).
- Latency budget p95 (§8): STT finalization **800 ms**, TTS start **300 ms** (plus M6's LLM TTFT 1500, tool 800, chat first token 1800). Over-budget turns get flags `over_p95_stt`, `over_p95_tts_start`.
- Per-turn record (§8) uses M5's `turns` table as is (no migration): `stt_ms = sttFinal − speechEnd` (browser clock, both from one browser), `tts_start_ms` measured on the **server clock** (see Rulings).
- The confirmation gate is untouched: no new path reaches `confirmAndExecute`, `propose` or a Calendar write. `tests/lint/write-path.test.ts` keeps passing. `interrupt` never executes, confirms or voids an earlier turn's action.
- `packages/core` stays lint-enforced pure. Don't touch `packages/evals/recordings` (another session owns PR #15).
- Browsers without recognition (Firefox) or with the mic denied show a clear message; typing keeps working.
- Never print `.env` values. A real booking (manual check) only with the user's go-ahead; cancel the event after.

## Rulings (decisions the spec leaves open)

1. **Push-to-talk = barge-in trigger.** The mic is only open after the caller presses the mic button (an always-open mic would hear our own speech). Pressing the mic while we are speaking **or** while a reply is in flight is "the caller starts speaking": stop speech, drop queued sentences, send `interrupt`. `onSpeechStart` while speaking does the same (covers a mic left open).
2. **What `interrupt` cancels.** The api aborts the turn's `AbortController`. Core checks the signal only at safe points: before each LLM stream round, after each streamed chunk, and before each tool call in `modelTurn`. It is never checked in `resolvePending` (classify → confirm/execute), `handOff` or after `pending_action` is emitted, so a "yes" already classified still executes and reports. An aborted turn throws `TurnInterrupted`; the existing catch voids a proposal made **this** turn (new void reason `"interrupted"`), and the session is not saved (the caller's text and the unheard reply leave no trace). The api sends `interrupted{}`, records no turn row. `interrupt` with no turn in flight is a no-op. The LLM HTTP call itself is not aborted (the provider interface has no signal yet); its output is discarded. Noted as a hole.
3. **`tts_start_ms` on the server clock.** The api notes when it sent each turn's first `agent_sentence` and, on the first `tts_started` for that turn, stores `receivedAt − sentAt`. Both are server times, so clock skew can't corrupt it; it includes one network round trip (≈0 on localhost). `at` is validated but not stored. Only turn ids this socket ran are accepted; later duplicates are ignored. If the turn row is already stored, `ConversationLog.setTtsStart` updates it (only while `tts_start_ms` is null).
4. **Spoken text after barge-in.** The browser mutes every `agent_sentence` until its next send (shown, not spoken). A final transcript that arrives while the interrupted turn is still unwinding is held by the controller and sent as soon as the chat is idle; the api likewise waits (instead of answering `busy`) for a turn it was asked to interrupt.
5. **e2e mock hook.** `createVoiceProviders()` returns `window.__frontdeskVoice` only when the build has `NEXT_PUBLIC_VOICE_TEST_HOOK=1` (set only in Playwright's web server env); every other build ignores it.
6. **Speak replies once voice is used.** Replies are spoken after the caller has used the mic once on this page; a typing-only caller hears nothing.

## Review Focus

1. **A spoken "yes" with no read-back pending.** Expected: an ordinary turn, nothing executed. Pinned in Task 6 › "a spoken yes with nothing pending runs a normal turn".
2. **Interrupt arriving during a confirm turn.** Expected: the booking executes exactly once and `action_result{executed}` is still sent; the interrupt neither cancels nor causes it. Pinned in Task 1 › "an abort during a confirm turn still executes once" and Task 2 › "interrupt during a confirm turn still reports executed".
3. **Interrupt after a proposal but before the read-back is sent.** Expected: the proposal is voided (`interrupted`), so a later "yes" can't confirm what the caller never heard. Pinned in Task 1 › "an abort after propose voids this turn's proposal".
4. **Final transcript lands before `interrupted`.** Expected: it's sent once the chat is idle, not dropped as `busy`. Pinned in Task 4 › "holds a final transcript until the chat is idle" and Task 2 › "user_text after interrupt waits for the cancelled turn".
5. **Forged `tts_started`** (another session's turn id, repeats, huge `at`). Expected: ignored, nothing written to someone else's row. Pinned in Task 2 › "ignores tts_started for a turn this socket didn't run".
